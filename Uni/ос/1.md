roujd-robin алгоритм - алгоритм выделения времени на выполнение процессов, который циклически перераспределяет между всему необходимыми к выполнению процессами (выделяет "кванты времени" на каждый процесс). Проблема алгоритма в том, что процессы, нуждающиеся в вводе данных для своего выполнения, могут большую часть выделенного времени ожидать ввода, получая недостаток времени для вычислений.

Многоуровневая очередь - очередь, в которой есть несколько "уровней" процессов, регулирующихся одинаковыми или различными алгоритмами.

### Процессы и потоки

При каждом вычислении времени, требующегося для выполнения процесса, мы определяем процесс в очередь "быстрых", "средних" или "долгих" процессов. Для каждой из очереди выделяется разное кол-во "квантов времени" (например, для "быстрых" процессов квант времени равен 32 милисекундам, а для "средних" - 64).
Поскольку время выполнения процесса вычисляется при каждои исполнении, очереди и группы динамически переопределяются

Объект планировщика задач:
кол-во очередей
алгоритмы планирования для каждой из очередей

ОС хар-уется обособдленностью процессов. Для каждого процесса имеется свое виртуальное адресное пространство, а так же свои выделенные ресурсы.

Потоки программы
Когда процессы необходимо запустить в пересекающемся виртуальном пространстве (выделить одно адресное пространство/одни доступные ресурсы), для разных процессов выделяются разные потоки.
Потоки исполняются параллельно, но имеют одинаковые права на адресное пространство и ресурсы, из-за чего надо согласовывать выполнение программ каждлого из потоков между собой.

Преимущества использовагния многопоточности:
Создание и уничтожение нового потока в существующем процессе значительно быстрее и экономнее открытия нового процесса.
Переключение потоков экономнее переключения между процессами
Множество потоков в одном процессе экономит адресное пространство и доступные ресуры7

Многопоточность более эффективна при:
Обработки одновременных и параллельных программ/событий

### Управление памятью

Распределяться должна вся незанятая оперативная память

Управление памятью со стороны ОС:
	1) Отслеживание свободной и занятой памяти
	2) Выделение и освобождение памяти
	3) Вытеснение процессов из оперативной памяти.
	4) Распределение памяти между процессами согласно их приоритету/очередли выполнения
	5) Защита областей памяти между процессами

Для управление памятьью исаользуется концепция иерархии памяти: некоторые части памяти компьютера архитектурно более быстрые, менее энергозатратные для доступа, тогда как другое - наоборот.

От самой быстрой:
1) Память ЦП
2) Кэш L1
3) Кэш L2
4) Основная память (оперативная)
5) Основное хранилище (жестки диск)
6) Внешняя память
7) Третичная память

Чем быстрее сегмент памяти к доступу, тем она более энергозатратна

Часть ос, управляющая абстракцией памяти называется диспетчером памяти

Кэш - копирование сегментов памяти в быстрое пространство оперативной памяти для быстрого доступа при повторном обращении (первое обращение идет из оперативной памяти и копируется в кэш при неоходимости)

Системная шина - магическое что-то, которое связывает устройства компьютера для общеения между собой
