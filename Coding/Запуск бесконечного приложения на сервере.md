
Чтобы запустить приложение на линукс-сервере так, чтобы оно работало без остановки, нужно использовать инструменты systemd.

Сначала нам нужно создать файл-энтрипойнт нашей программы. В некотором смысле, это должна быть main-программа, которая будет реализовывать ожидаемое поведение и обращаться к соответствующим сорс-файлам (какая бы файловая структура проекта ни была).

Далее нам нужно создать .service файл, в котором будет содержаться информация о том, чего мы ожидаем от запуска программы.
Положим сервис файл по пути: /etc/systemd/system/filename.service
На самом деле файл можно назвать как угодно, но желательно называть его именем приложения, за которое этот файл отвечает, чтобы это название имело смысл - название файла потом может быть использовано в других местах.
Так, назовем файл tgbot.service. Приведем пример его заполнения:

#### Заполнение .serivce файла
```
/etc/systemd/system/tgbot.service:

[Unit]
Description=Main service for running this tg bot
After=network.target
StartLimitIntervalSec=0

[Service]
Type=simple
Restart=always
RestartSec=1
User=root
ExecStart=[command] /usr/local/bin/path-to-exec

[Install]
WantedBy=multi-user.target
```

#### Значения заданных полей:

**Description** - описание, которое будет выводиться при запуске сервиса. Не так технически важно, как оно будет заполнено.

**After** - поле, которое означает, после запуска какого процесса на сервере должен запускаться наш сервер. При значении `network.target`, сервис запускается сразу, как будет запущена сеть на сервере (еще можно ставить значение `network.online.target`, если для работы нашего сервиса важно взаимодействие по сети). Однако в это поле можно так же передать названия любого нашего сервиса, лежащего на сервере. Например, если наш данный сервис зависит от сервиса с базой данных, который называется sqlser.service, мы можем написать `After=sqlser.service`.

**StartLimitIntervalSec** - значение 0 гарантирует, что systemd не перестанет пытаться поднять наш сервис вне зависимости от того, сколько раз он не сможет это сделать.

**Type** - по умолчанию simple. Это значит, что наш сервис запускается "сразу", как поступит такая команда. Тип simple не стоит использовать, если от запуска данного сервиса зависит работа других.

**Restart** - директива о том, как и при каких условиях система должна перезапускать сервис после того, как он прекратил работать (например, если в коде случилась необработанная ошибка). `always` подразумевает, что сервис будет перезапускаться всегда после падения (а `StartLimitIntervalSec=0` гарантирует, что система будет пытаться поднять сервер, пока мы ей сами не скажем перестать это делать).

**RestartSec** - количество секунд, которое мы даем нашему серверу "на отдых" перед очередной попыткой поднять наш сервер. Большее значение = меньшая нагрузка на сервер в ситуациях, когда сервисы начинают падать.

**User** - поле с именем пользователя на этом сервере.

**ExecStart** - Команда, запускающая поведение нашего сервиса.

**WantedBy** - хз че такое. Что-то про группы сервисов, которые вместе запускаются при определенных условиях или чето такое

### Чтобы запустить сервис вручную, 

надо запустить команду `sudo systemctl start tgbot.service`
